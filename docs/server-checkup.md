Server and worker checkup

Folder import keeps the existing `{added, duplicates, errors}` response. Each request processes at most 100 audio files and 10,000 directory entries, with a 30-second ingestion budget. Discovery streams directory entries instead of loading entire folders. Hashing, metadata reads, and copies stop on cancellation; unfinished track copies are removed. Completed tracks and preparation jobs remain saved. When a limit is reached, `errors` tells the host to import smaller subfolders to finish. This avoids a background-job protocol or UI changes; it does not add automatic continuation for large folders. Multipart bodies still stream to temporary files, but hashing, metadata parsing, and managed copies run one file at a time.

Login failures use a rolling ten-minute window with a 15-failure per-client limit and a 100-failure global backstop. The client key uses the first `x-forwarded-for` address, then `x-real-ip`, then a bounded user-agent fallback. This is best-effort grouping, not trusted identity: the app runs Next directly without a reverse proxy, clients can supply these headers, and Next only fills `x-forwarded-for` when absent. Next's Request API has no socket address. A trusted reverse proxy would need to overwrite forwarding headers; clients with the same fallback user agent share a bucket.

The global count is independent of client keys, bucket eviction, and successful logins, so rotating forged headers cannot permit more than 100 failed password guesses in any ten-minute window. At 100 failures all password-verification attempts are throttled, including the host's, until failures expire. The higher global cap allows several clients to exhaust their 15-failure buckets without immediately locking out the host, while bounding a spoofing attack. Successful verification clears only that client's failures. Expired buckets are removed and the client map holds at most 10,000 entries. Both limits are in memory within one server process: restarting resets them, and multiple processes would require a shared limiter. Existing scrypt verification adds work per admitted guess; no sleeps are added.

SQLite migration steps run in one immediate transaction and advance `user_version` only on success. Version 0 establishes the base schema; version 1 adds missing model/generation columns and alignment tables, tolerating already-present additions. Existing version 2 databases keep their schema and data. New schema changes should append a migration. Databases from a newer app are rejected rather than downgraded.

Positive LRC file offsets move lyrics earlier, so the parser subtracts the offset and clamps both line and word timing to zero. The LRC library's format reference describes positive offsets as shifting time up: https://github.com/weirongxu/lrc-kit/blob/master/README.md.
